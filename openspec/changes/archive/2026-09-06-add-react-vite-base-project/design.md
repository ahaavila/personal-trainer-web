## Context

The repository is currently empty of application code (only `.github/` and `openspec/` exist). See proposal.md - Why for motivation. This design covers scaffolding the initial React + Vite project at the repository root.

## Goals / Non-Goals

**Goals:**
- Stand up a working React + Vite + TypeScript project at the repo root using the official Vite scaffolding tool.
- Provide standard dev/build/preview/lint scripts.
- Keep the starter page minimal and generic so it doesn't presume future feature direction.

**Non-Goals:**
- No routing, state management, styling framework, or testing framework setup — those are left to future changes.
- No CI/CD pipeline or deployment configuration.
- No backend/API integration.

## Decisions

- **Use `npm create vite@latest . -- --template react-ts`**: Generates the official, actively maintained Vite + React + TypeScript scaffold rather than hand-rolling config, reducing setup errors and keeping upgrade paths standard.
  - Alternative considered: Create React App — deprecated/unmaintained, slower dev server; rejected.
  - Alternative considered: Next.js — adds SSR/routing conventions not needed for a base scaffold; rejected as out of scope for this change.
- **TypeScript over plain JavaScript**: Aligns with the `react-ts` template default and gives type safety for future feature work at negligible setup cost.
- **Root-level project (no monorepo/subfolder)**: Repository currently has no other app code, so a single root-level app avoids unnecessary structure.
- **Keep ESLint config generated by the Vite template**: Provides sensible React/TypeScript defaults without introducing extra decisions in this base-scaffold change; can be extended later.

## Risks / Trade-offs

- [Risk] Generated scaffold pulls in a specific set of dependency versions that may need updating soon after creation → Mitigation: run `npm install` fresh at implementation time to get current template versions.
- [Risk] Minimal starter page may need replacing quickly once real feature work starts → Mitigation: keep starter content trivial and clearly a placeholder, not a design system commitment.
